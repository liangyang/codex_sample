2. Agentの運用ガバナンスが、モデルの外側に独立した製品層として立ち上がる

根拠: AWS / Microsoft / GitHub / 中国企業の公式情報領域: Agents / Governance / Security

AWS Agent Registryの一般提供、MicrosoftのResponsible AI整理、Developer Readsの組織既定モデル・段階的レビュー承認・ユーザー別予算制御、さらに中国のWorkBuddy開放平台が、同じ方向を示しました。必要なのは、AgentやSkillを増やすことではなく、所有者、権限、承認、版、監査、費用、廃止を一つの台帳で追うことです。

5. 開発者の主戦場が、機能追加から測定可能なライフサイクルへ移る

根拠: Developer Reads / GitHub / AWS / NVIDIA 公式領域: Evals / CI / Inference / Delivery

今週のDeveloper Readsは、長時間タスク向けAPI、AgentとSkillのカタログ、安全性評価の閉ループ、機密コードの除外、レビュー承認、リアルタイム予算、CodeQL、ローカル推論ルーター、CUDA最適化を扱いました。個別の新機能ではなく、設定・評価・実行・観測・改善を同じリリースサイクルへ入れる材料が揃っています。

小さな代表タスクをセッションごと再生し、完了率、ツール失敗、再試行、レビュー時間、TTFT、P95、費用、権限漏れを記録する。これがモデルやAgentを替えたときの比較可能性を作ります。

何が変わったか

  • 能力とアクセスが分離した: 同じ基盤から、一般用途、企業用途、サイバー・生物などの高リスク用途を別の審査と保護で提供する設計が標準候補になりました。
  • Agentが資産になった: Agent、Tool、Skill、MCPサーバーは、作って終わりではなく、登録、承認、版管理、利用状況、所有者、廃止まで管理する対象になりました。
  • 移行可能性が品質要件になった: 障害、料金変更、提供終了、地域制限を前提に、同じタスクを別モデルへ逃がせる構成が必要です。
  • 中国の評価軸が現場へ寄った: Token課金、サービス商、算力、ロボットの作業単位、販売チャネルが、モデル性能と並ぶ導入条件になっています。
  • 削ったもの: 週の構造を変えない単発の資金調達、展示だけの期待値、独立確認のない性能・契約数字はTopから外しました。
