5. 中国と世界の両方で、AIの評価軸が「賢さ」から「運用可能性」へ揃ってきた

根拠: 週次アーカイブ横断領域: Economics / Adoption

OpenAI の scorecard、Google の ATLAS、GitHub の impact dashboard、AWS の benchmark、北京市の Token 経済支援は別々の話に見えて、実際には同じ方向です。企業も政府も、AIをベンチマークの印象ではなく、仕事完了量、利用定着度、請求条件、失敗率、再現可能な評価で測ろうとしています。来週以降も、派手な発表より測定基盤の整備が採用速度を決めそうです。

何が変わったか

  • 新しく主役化: health、voice、calendar、issue、code review のような業務導線へ AI が直接つながる話が増えました。
  • 重要度が上昇: approval、confidence、billing、benchmark、sandbox、usage telemetry が、開発者向けAIの標準部品になりつつあります。
  • 中国で継続: 新モデル競争は続いても、実務の差は API 名称、価格表、移行締切、地方補助、备案条件でつく流れが強まりました。
  • 削ったもの: 単発の資金調達、人事、展示演出、個別アプリ機能の細かい追加は、週を貫く配布・制御・運用の構造に効くものだけ残しました。

開発者への示唆

  • 権限設計: health や calendar のような接続機能は、便利さより先にデータ境界、許可単位、監査ログを設計する。
  • agent 運用: approval と confidence を実装し、低リスクだけを自動適用して高リスクは review に残す。
  • 評価基盤: prompt の感触ではなく、task-state benchmark、usage telemetry、失敗率、ロールバック時間で agent を測る。
  • eval 安全: 能力評価、ネット接続、認証情報、実運用データを同じ箱に入れず、評価環境を隔離する。
  • 中国配布: 中国向け導入では、モデル性能表より先に、移行期限、価格更新、备案、補助、提供地域を確認する。
  • コスト管理: token 単価ではなく、成功タスク単価、再試行回数、review 工数、追加監査コストまで含めて採算を見る。
