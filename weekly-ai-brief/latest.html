5. 開発者の評価単位が、回答品質から「行動単位」と工程全体へ移った

根拠: Developer Reads / GitHub / Mistral / NVIDIA

今週のDeveloper Readsは、コーディングAgentを行動単位で評価し、ハーネスの反復改善、権限強制、GPU共有、Encode・Prefill・Decode分離、反復検索、段階的なコード移行を扱いました。共通するのは、モデルを一度採点するのではなく、計画、ツール実行、テスト、レビュー、復旧までを再現可能な工程として測ることです。

完了率に加えて、ツール失敗、再試行、レビュー時間、P95、費用、権限違反、復旧成功率をセッション単位で記録すると、モデルやAgentを替えても比較できます。

何が変わったか

  • 実行基盤が製品になった: 長時間セッション、ホスト環境、ツール、サブエージェント、音声、業務データをまとめて買う構成が増えました。
  • 安全性が運用設計になった: 評価環境の誤設定、外部接続、資格情報、承認、開示、復旧を一続きで確認する必要があります。
  • 移行性が品質要件になった: 旧モデルの自動切替、価格変更、障害、退役、ピーク課金を前提に構成を作る段階です。
  • 中国の導入競争が現場へ寄った: サービス商、金融、公共窓口、算力、ロボット、職種が、モデルの数より重要な実装単位になっています。
  • 削ったもの: 週の構造を変えない資金調達、展示だけの期待値、独立確認のない性能・導入数字はTopから外しました。
