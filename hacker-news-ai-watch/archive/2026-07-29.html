3. Stateless MCP transport moves state into explicit contracts

114 pts37 commentsArea: MCP

Signal: The MCP 2026-07-28 specification update, summarized by its maintainers as transport going stateless, crossed 100 points. For implementers, removing implicit connection state does not remove state from the system; it makes request identity, resumability, authorization, retries, and lifecycle ownership design choices that must be visible.

Why read: Confirm normative changes in the specification and migration guidance. Test reconnects, duplicate requests, concurrent clients, cancellation, capability negotiation, token rotation, and tracing across intermediaries. Keep protocol-level state separate from application memory and do not assume a transport session is an authorization boundary.

World AI News Connection

Today's HN reaction connects frontier-model capability to the less glamorous systems around it. Security discovery, cryptanalysis, and scientific coding become useful only when permissions, evidence, deterministic checks, and accountable handoffs are part of the product rather than post-hoc safeguards.

The MCP transport change points in the same direction at protocol level: implicit state and trust are being replaced by contracts that developers must implement and test. Agent platforms should therefore version not only models and prompts, but also tool schemas, identity rules, transformations, audit records, and recovery procedures.
