ローカルのコーディングエージェントをプロジェクト単位で隔離する

GitHub / 2026-09-23 / Safety・Coding Agents

読む価値: ローカル実行のファイル読み書き、ネットワーク、GitやCLIの資格情報をプロジェクトごとに制限できます。OSが要求した隔離を適用できない場合は、サンドボックスなしで続行せずシェルを停止する設計です。

開発者への示唆: エージェントの権限はプロンプトだけで縛らず、実行環境で強制する必要があります。設定は既定で無効、変更は新規または再起動後のセッションに適用される点にも注意が必要です。

試すなら: テスト用リポジトリで読み取り専用領域、書き込み許可領域、拒否領域を設定し、外部通信と資格情報へのアクセスを確認します。意図的に制限外の操作を試し、失敗が記録されることも確かめてください。

スキルを使うエージェントの選択ミスと手順抜けを分けて測る

AWS / 2026-09-22 / Evals・Agents

読む価値: エージェントの最終回答が自然でも、手順書の選択を誤ったり、必須の確認を飛ばしたりすることがあります。実行記録からスキルの選択精度と指示への追従度を別々に評価し、指定スキルの読み込みは決定的な検査で確認する方法を示します。

開発者への示唆: 集計スコアだけでは修正箇所が分かりません。選択の誤りはスキル記述の重複、手順抜けは手順構成やガードの不足というように、失敗の種類ごとに直せます。

試すなら: 代表的なタスクを各スキルに用意し、正しい選択・必須手順・スキル未読込を別々に検出する回帰テストを作ります。記録済みトレースをCI評価に使い、少数ケースで判定基準を人手確認してください。

同時実行数を振って生成AIエンドポイントを適正化する

AWS / 2026-09-22 / Inference・Infra

読む価値: 同時リクエストを段階的に増やし、スループットが頭打ちになる地点と、遅延がSLAを超える地点を測るベンチマーク手順です。入力長・出力長・ストリーミングを実際の負荷に寄せ、APIから自動測定を回せます。

開発者への示唆: 平均速度だけで台数を決めると、ピーク時の待ち行列か過剰なGPU費用につながります。p99、初回トークン時間、スループットを同じ負荷曲線で比較するのが実務的です。

試すなら: 自分の入力・出力分布を使い、同時実行数ごとにp99、初回トークン時間、出力速度を記録します。SLAの境界を容量計画に反映し、検証後は課金対象リソースを削除してください。
