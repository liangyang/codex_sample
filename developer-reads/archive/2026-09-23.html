機密推論の安全性と速度を同じベンチマークで測る

NVIDIA / 2026-09-22 / Safety・Inference

読む価値: 暗号化メモリやGPU間通信を使う機密実行では、データ保護の追加コストが推論の前処理・生成・通信に現れます。安全機能を有効にした状態と無効にした状態を、同じ入力長・同時実行数で比較する方法が具体的です。

開発者への示唆: 「機密実行対応」をチェックボックスで終わらせず、長い入力・長い出力・低同時実行など、自分の負荷でオーバーヘッドを測る必要があります。セキュリティ設定と推論最適化は別チームの作業ではありません。

試すなら: 代表的な入力長と同時実行数を固定し、安全機能の有無でp50/p95レイテンシ、入力処理速度、出力速度、GPU使用率を比較します。測定結果に、証明書・構成・ドライバの版も添えてください。

AIエージェントでROS 2ノードのGPUデータ経路を移行する

NVIDIA / 2026-09-22 / Agents・Infra

読む価値: GPU計算を速くするだけではROS 2全体は速くならず、CPUへのシリアライズやコピーがボトルネックになります。既存ノードのデータ移動を追跡し、GPU上のバッファを維持しながら標準インターフェースとCPUフォールバックを残す流れを示します。

開発者への示唆: コーディング支援を使った高速化でも、成果物はコード差分だけでは足りません。変更前後のグラフ、コピー回数、メッセージ遅延、フォールバック時の正しさを検証する仕組みが必要です。

試すなら: 既存のCUDA対応ノードを一つ選び、入力から出力までのCPU/GPU間コピーをプロファイルします。移行後は同じセンサー再生データで、エンドツーエンド遅延、CPU使用率、出力一致、CPU経路の動作を比較してください。

複数GPU推論を一つのサービス境界にまとめる

NVIDIA / 2026-09-21 / Inference・Infra

読む価値: 一つの推論ネットワークを複数GPUで実行し、クライアントからは一つのサービスとして呼び出す構成を解説しています。GPU間の集団通信や実行コンテキストをサーバー側に閉じ込め、長い生成処理の待ち時間を短縮する考え方が分かります。

開発者への示唆: 複数GPU化は、GPU台数を増やせば比例して速くなる話ではありません。通信、固定的な後処理、バッチ形状、モデルを分割して準備する手順を含めて、サービス全体のレイテンシを測る必要があります。

試すなら: 単一GPU・2基・4基・8基で同じリクエストを流し、推論部分とクライアント側処理を分けて計測します。台数ごとの速度向上だけでなく、通信量、GPU利用率、運用コスト、障害時の縮退方法も記録してください。

DNSまで含めてマルチテナントの実行境界を閉じる

AWS / 2026-09-21 / Safety・Agents

読む価値: テナントごとのデータを扱うAI生成コードを、専用アカウント、DNSファイアウォール、VPCエンドポイント、ジョブ単位の一時認証情報で隔離した事例です。HTTPやポートだけでなく、DNSや認証情報の経路まで脅威モデルに含めています。

開発者への示唆: サンドボックスの安全性は、プロセス分離だけでは決まりません。実行環境が到達できるサービス、名前解決先、許可するデータ、資格情報の寿命をネットワーク側でも制限し、継続的な流出テストで確認する必要があります。

試すなら: 自分の実行環境で、許可する宛先を明示した deny-by-default の表を作ります。HTTP、DNS、メタデータ、別テナントのストレージへの到達を自動テストし、ジョブ終了後の認証情報失効も検証してください。
