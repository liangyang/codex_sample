Safety Infra

GitHub Actions holds potentially malicious workflows for approval

出典: GitHub Changelog / 公開日: 2026-07-28 JST

読む価値: public repository の workflow が疑わしいと GitHub 側で止まり、write 権限のある collaborator の承認が必要になります。CI/CD の前提が、実行より先に検査する方向へ寄りました。

開発者への示唆: 供給網攻撃は、もはや repository の外側だけを見ていても防げません。workflow の承認フロー、通知、復旧を運用設計に含める必要があります。

試すなら: 重要な public repo で承認担当と通知経路を確認し、止まったときに誰が何をするかを明文化してください。

Safety Infra

Dependabot alerts on malicious packages across more ecosystems

出典: GitHub Changelog / 公開日: 2026-07-28 JST

読む価値: OpenSSF の malicious-packages データが GitHub Advisory Database に入ったことで、npm や PyPI などの malware 覆域が広がりました。依存関係の監視が一段深くなります。

開発者への示唆: 依存更新の通知だけでは不十分で、悪性公開の早期検知まで含めた supply chain ガードが必要です。特に広い ecosystem を使うプロダクトほど効果が出ます。

試すなら: `type:malware` を前提に、主要 repo の Dependabot 設定とアラート受信先を見直してください。

Agents Coding Agents

Enterprise managed settings in the GitHub Copilot app and Copilot cloud agent

出典: GitHub Changelog / 公開日: 2026-07-27 JST

読む価値: Copilot app と cloud agent が、CLI や VS Code と同じ managed settings を共有するようになりました。policy、plugin、approval prompt の統制を揃えやすくなります。

開発者への示唆: agent surface が増えるほど、設定の分断が事故になります。管理者側は「どの client でも同じガードレール」が実現できるかをまず確認すべきです。

試すなら: 既存の managed settings を流し込み、Copilot app と cloud agent で同じ制御が効くかを確認してください。

Agents Governance

Manage GitHub Copilot app access with a dedicated policy

出典: GitHub Changelog / 公開日: 2026-07-27 JST

読む価値: Copilot app が CLI から独立した policy を持ち、enterprise と organization で個別に制御できるようになりました。導入と封じ込めの両方がやりやすくなります。

開発者への示唆: クライアント別に許可範囲を変えたい組織では、policy の独立が運用コストを下げます。逆に、既定設定の見落としは増えるので rollout 計画が必要です。

試すなら: AI Controls で app policy を確認し、先行導入する org と止める org を分ける基準を決めてください。

Coding Agents Infra

GitHub Copilot for JetBrains adds improved OpenTelemetry configuration and model management

出典: GitHub Changelog / 公開日: 2026-07-27 JST

読む価値: JetBrains 側で OpenTelemetry export、token 上限、model management、MCP server 接続が強化され、IDE 内の agent work を見える化しやすくなりました。

開発者への示唆: ローカル agent の実務価値は、速度だけでなく観測と再現性にあります。custom endpoint や BYOK を使うチームほど、この更新の恩恵が大きいです。

試すなら: OTel export を有効化し、同じ task で token 消費と失敗箇所の差を見てください。
