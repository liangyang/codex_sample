AWS / 2026-09-14 / Agents・Safety・API

読む価値: 開発支援エージェントがGitHubやSlackなどへ接続するとき、利用者のログイン、個別スコープの同意、セッション結合、トークン保管、監査までを一つの流れで確認できます。

平均精度だけでなく再現性を測る

Hugging Face / 2026-09-15 / Evals・Agents

読む価値: 平均成功率が高くても、同じ課題を繰り返すと結果が揺れる問題を、全試行で成功する割合と意思決定ごとの揺れに分解しています。記録済みの軌跡を再サンプリングする診断手順と、オープンソース実装も紹介されています。

開発者への示唆: 「一度は解けた」と「同じ依頼を安定して解ける」は別の品質軸です。Mean@kだけでなくPass^kとその差を回帰指標に加えると、ツール選択・引数・再試行など、成功と失敗を分ける決定点を見つけやすくなります。

試すなら: 代表課題を20本以上選び、各課題を5回実行して平均成功率と全試行成功率を併記します。軌跡を保存し、揺れやすい決定点をオフラインで再評価したうえで、プロンプト・ツール説明・検証手順を変え、平均精度を落とさず差が縮むか確認してください。

自動選択でコストと品質の重みを設定する

GitHub / 2026-09-14 / Coding Agents・API・Infra

読む価値: 自動的なモデル選択に、効率重視・バランス重視・品質重視の3段階を設け、同じ選択機構でもタスクごとに費用、品質、応答時間の優先順位を変えられるようにした変更です。

開発者への示唆: 自動ルーティングは「常に最良」ではなく、組織やタスクごとのポリシーです。単純な補完、レビュー、設計相談などを同じ重みで扱うと、品質を必要以上に買うか、重要な作業で費用を削りすぎるため、用途別の基準と利用量の可視化が必要です。
