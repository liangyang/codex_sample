Agents Coding Agents

Agent automation controls in GitHub Issues in public preview

出典: GitHub Changelog / 公開日: 2026-07-23 JST

読む価値: GitHub Issues に approvals, confidence, rationale が入り、ラベル付けや担当割り当てを review 前提で流せるようになりました。REST と GraphQL でも扱えるので、issue automation を実運用の制御面として設計できます。

開発者への示唆: issue automation は「自動化するかどうか」ではなく、「どの confidence なら自動適用するか」の設計問題です。高リスク変更だけを review に寄せると、速度と監査性の両立がしやすくなります。

試すなら: 低リスクの repo で suggestion mode を有効にして、どの action が review に残るか、rationale が triage で本当に役立つかを観測してください。

Coding Agents API

Claude Opus 5 is now available in GitHub Copilot

出典: GitHub Changelog / 公開日: 2026-07-24 JST

読む価値: Claude Opus 5 が Copilot に入り、長時間の coding task、複数ツールの協調、regression verification を狙うモデル選択肢が増えました。Copilot のモデル選択が、単なる好みではなくワークフロー設計になります。

開発者への示唆: 複雑な refactor や自動修正の成否は、モデル単体より「どの作業を任せるか」「どこで止めるか」で決まります。高性能モデルほど、policy と評価セットを先に決めた方が安全です。

試すなら: いまの既定モデルと Opus 5 を、同じ failing test と multi-file refactor で比べ、diff の大きさ・再試行回数・人間の修正量を見てください。

Agents Coding Agents

Copilot cloud agent for Linear is now generally available

出典: GitHub Changelog / 公開日: 2026-07-23 JST

読む価値: Linear の issue を Copilot cloud agent に割り当てると、draft pull request を作成し、GitHub Actions ベースの一時環境で進め、完了時に review を求めます。issue tracker が async work の起点になりました。

開発者への示唆: agent の制御点は、issue 本文だけでなく、モデル・branch・カスタム agent まで含むようになっています。作業の入口を Linear に寄せるなら、ブランチ規約とコース修正のルールを先に決めるべきです。

試すなら: 1 つの Linear キューで pilot を走らせ、time-to-PR と review 往復回数を測りつつ、コメントでの指示変更がどこまで効くか確認してください。

Infra API

GitHub MCP Server supports the next MCP specification

出典: GitHub Changelog / 公開日: 2026-07-23 JST

読む価値: MCP が 2026-07-28 から stateless になるのに合わせ、GitHub MCP Server が新 spec に先行対応しました。sessions と initialize が外れ、並列 handshake しやすくなるのが大きいです。

開発者への示唆: remote tool server の設計は、stateful session を前提にしたままだと移行で詰まります。MCP 接続の resume や tool 選択が状態に依存していないか、今のうちに点検した方がいいです。

試すなら: 既存の MCP client/server を next spec 相当で一度つなぎ、session 管理や認証まわりの暗黙前提がどこにあるか洗い出してください。

Evals Infra

AWS announces aws-bench, an open-source benchmark for AI agents on AWS

出典: AWS What's New / 公開日: 2026-07-24 JST

読む価値: AWS 上の real-world tasks を再現する research preview の benchmark で、ground-truth と CLI を使って agent を採点できます。評価対象が cloud task state まで落ちているのが実務向きです。

開発者への示唆: agent の良し悪しは、プロンプトの感触より task-state ベースの再現性で見る方が強くなっています。infra 系の agent ほど、benchmark と harness の整備が成果を左右します。

試すなら: ひとつの内部 agent か harness を aws-bench に通し、自前の cloud-task eval と照らして failure mode の差を確認してください。
